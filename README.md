# Document Management System (doc-mgmt)

Internal document management for one organization, built with Laravel 13 and Filament 5.

## Current implementation

- Document metadata management and Filament resources for core reference data.
- Private file uploads with SHA-256 checksums and version history.
- Authorized download route for the current published version, with download audit records.
- Sequential/parallel review-cycle service, reviewer decisions, publication, replacement, and archive actions.
- Reviewer assignment notifications, a reviewer pending queue, and rejection-reason validation.
- Recent audit activity table for administrators and document managers.
- Dashboard statistics and recent documents.
- Configurable expiry and next-review reminder schedules and recipient groups per document type.
- In-app database notifications with duplicate prevention and retry handling.
- Role and visibility policy foundations with initial access-policy tests.

This is an active first implementation, not yet production-ready. See docs/ROADMAP.md for remaining work and validation gaps.

## Requirements

- PHP 8.4.1+
- Composer 2
- MySQL
- Filament 5 compatible with Laravel 13

## Local setup

1. Clone this repository.
2. Run composer install.
3. Copy .env.example to .env.
4. Create the MySQL database configured by DB_DATABASE and update DB_USERNAME / DB_PASSWORD.
5. For the first local setup only, set DMS_ADMIN_EMAIL and DMS_ADMIN_PASSWORD in your local .env file. Do not commit credentials.
6. Run php artisan key:generate.
7. Run php artisan migrate --seed.
8. Run php artisan serve and open /admin.

The seeder creates the default Operations department, General category, Internal Document type, and a sequential review policy. It creates the initial administrator only when DMS_ADMIN_EMAIL and DMS_ADMIN_PASSWORD are provided.

## File security

Document files are stored on the private disk under storage/app/private/documents, outside the public web root. Do not create a public storage link for this directory. Downloads must go through the authenticated, policy-checked route.

## Notifications and reminder scheduler

Review assignments generate database notifications immediately. Expiry and next-review reminders are generated by `dms:process-reminders`, scheduled daily at 08:00 in the configured application timezone. Run Laravel's scheduler every minute in production. Administrators configure reminder offsets and recipient groups under Document Types. Notifications are stored in the database only; a complete Filament notification inbox/read-state UI is still outstanding. See [docs/NOTIFICATIONS.md](docs/NOTIFICATIONS.md) for migration, configuration, scheduler activation, and verification instructions.

## Important

The current implementation includes the initial review UI and workflow endpoints, but notification read-state UX, expanded rejection strategies, reminder operations dashboard/failure visibility, complete tests, backup/recovery instructions, and production hardening remain in the roadmap.
